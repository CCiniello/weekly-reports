Executive summary — post to Slingshot

React SEO: adoption is climbing — now we win the grid SERP

Two-line version: React ranks across its core terms and npm adoption is up, but the grid head terms sit at the page-1 floor where clicks are thin. The work now is execution, not strategy.

What's working

Momentum. Clicks rebounded to 145 (+6.6% WoW) after last week's dip, all-React sessions rose ~11%, and the north star — npm installs — is up +19% MoM (June 41,594). Branded terms own #1, and “react gauge” (#13 → #9) and “react grid component” (#26 → #16) both climbed.

What's not

The money term “react data grid” is stuck at #10 — the page-1 floor, seven off the Sep-30 top-3 goal — and “react chart” slipped off page one (#10 → #13). Two of the three #1-goal head terms (react grid, react table) still aren't tracked, so we're partly blind on the core goal.

The priority this week
  • Instrument the goal — add “react grid” & “react table” to Rank Tracker 1076972.
  • Push the grid — on-page depth + internal links to move “react data grid” off the page-1 floor.
  • Investigate the “react chart” page-one slip; route top blog traffic to the product/grid pages.
  • Fix the plumbing — restore the npm live pull and stand up React-specific AI-visibility prompts.
For leadership

Demand and adoption are trending the right way — npm +19% MoM, clicks recovering. The constraint is getting the grid head terms off the bottom of page one; as that happens, product-page traffic and conversion should follow. Two measurement gaps (npm live pull, React-scoped AI visibility) are being closed so next week's read is cleaner.

Two things live here: (1) our source of truth — which tool is the authority for each number and why, so nobody compares two tools that measure different things; and (2) a plain-English SEO glossary so anyone reading the report knows what the terms mean. The rule underneath it all: one metric, one tool — a trend is only trustworthy if it comes from the same place every week.

SEO glossary — plain English
TermWhat it meansWhere / why we track it
KeywordA word or phrase people type into search (e.g. “react data grid”). We group related keywords into clusters around one page.Ahrefs for volume; Rank Tracker / GSC for how we rank.
Head term vs. long-tailA head term is short and high-volume (“react data grid”). A long-tail keyword is longer, more specific and lower-volume (“lightweight react data grid”) — less traffic each, but easier to rank for and higher intent.Ahrefs (find them) + Rank Tracker (track them).
ImpressionsHow many times our page showed up in search results for a query — whether or not anyone clicked.GSC.
Clicks & CTRClicks = people who actually clicked through. CTR (click-through rate) = clicks ÷ impressions. Low CTR at a good position usually means a weak title or an AI Overview taking the click.GSC.
Position / rankingWhere our page sits in Google results for a query. Page 1 = positions 1–10 (almost all clicks); page 2 = 11–20 (almost none). The “page-1 floor” is ~#10.Ahrefs Rank Tracker (ours); GSC (clicks).
KD (Keyword Difficulty)Ahrefs' 0–100 estimate of how hard it is to rank in the top 10 for a term. Higher = more on-page + links needed.Ahrefs.
Domain Rating (DR)Ahrefs' 0–100 score of a site's overall backlink strength / authority. Higher DR makes it easier to rank. Ours is 72; goal is 74.Ahrefs.
npm installsHow many times our React packages are downloaded from npm each month — the closest thing to real product adoption, and our north-star metric.public npm downloads API.
Technical healthA crawl-based score (0–100) of how clean the site is — broken links, errors, redirects, sitemaps. Low health caps how high anything can rank.Ahrefs Site Audit.
AI visibility (AEO)How often AI answers (Google AI Overview, ChatGPT) mention our brand for relevant questions — the AI-era version of ranking. AEO = Answer Engine Optimization.Amplitude AI Visibility.
Share of voiceOf all the AI answers to a set of questions, the % that mention a given brand — how loud we are vs. competitors in AI answers.Amplitude.
Cluster / not trackedA cluster is a group of related keywords one page should own. Not tracked means we have the demand but the term isn't in the Rank Tracker yet (e.g. react grid, react table).Rank Tracker + GSC.
The one rule: one metric, one tool — never blend sources for the same number. When two tools disagree, they're usually measuring two different things (search vs. on-site, our real data vs. a model's estimate), not contradicting each other. Volatility: WoW on clicks/impressions, not raw position; flag a position move only if ≥3 positions OR crossing the page-1 boundary (10↔11); for the #1-target grid terms, also flag any slip from #1.
